# Plan 055 Phase 4 verification notes

- [x] Expression lookup checks lexical bindings, then the operation registry, then the environment for `ENV-NAME`. `std/NAME` selects the registered operation independently of lexical bindings. `TestNativeExpressionNamesResolveLexicalStandardAndEnvironment` covers lookup precedence, lowercase names, missing and denied reads, and fallback. The WASM probe verifies the same environment and standard-library lookups.
- [x] Direct command lookup prefers lexical callees and rejects lexical non-callables before evaluating arguments. Plain command names use the executable resolver without consulting the standard library. Explicit `std/`, `x/`, and standalone typed command heads select the intended target. Direct `out!` and `err!` reuse the library operations. `TestNativeKashCommandLookupPrefersLexicalBindings` and `TestNativeInteractiveCommandLookupPrefersSessionBindings` cover precedence, typed arguments, and session dispatch.
- [x] `TestKashInteractiveBuiltinsRequireASession` covers batch and rule-body diagnostics, including nested pipelines and capture. Alias and option formatting still supports interactive startup text.
- [x] `out!` and `err!` route their library operation bytes through pipes, captures, redirections, async handles, and deferred cleanup. Native and WASM checks cover binary data, stderr duplication, and output routing without run authority when no executable is involved.
- [x] Standalone function invocations support `$(…)`, `$?(…)`, and async outcomes read with `wait`. Native and WASM checks cover ordered output from the evaluator, child processes and defers, typed return values, retained failure diagnostics, accepted exits, capture-limit enforcement, and capability denial.
- [x] `$?(…)` and `$&(…)` preserve the last reached command-list operand's outcome. For process outcomes, value includes stdout from all reached operands. A final function keeps its typed return value. Native and WASM checks cover short-circuit selection, accepted exits, executable lookup failure, timeout, fallback, and a shared capture limit.
- [ ] Route user-defined callables with live stdin and stdout/stderr through process graphs.
- [x] Direct `wait` resolves owned async handles. Native and WASM checks cover external commands and command lists started with `$&(…)`, repeated waits, captured stdout, accepted exits, and executable lookup failures. The native tests cover terminal handle dispatch alongside terminal job selectors and unobserved failures at the final join.
- [x] Direct `kill` cancels owned async handles, and an explicit signal targets the handles' process requests. Native and WASM checks cover signals sent during startup, cancellation of running children, outcomes read via `wait`, and isolation from other jobs. The native tests check reaping and reject PID operands. Terminal job selectors continue to use job control.
- [x] File-backed `module/dir` and `module/file` resolve against the authoring source independently of `cd`. Native and WASM checks cover an included Kash helper, path interpolation, a Kame rule body, and a loaded Kash library. A lexical `env` binding can coexist with `env/NAME`.
- [x] Reserved and invalid namespace stems and reserved explicit aliases produce `DEF_INVALID` in Kame and Kash. An explicit valid alias permits a reserved or invalid stem. Direct `from` aliases remain value bindings. Importing a document template produces `RES_INVALID`.
- [x] Bind authored import namespaces and `from` names in their declaring files. Native and WASM checks cover cross-language imports, nested imports from included files, callable facades, private exports, and import cycles that name the chain. Native watch recovers a missing nested module and reloads its callable after an edit.
- [x] Imported Kame modules select conditional includes from definitions already in scope. Native and WASM checks cover nested branches, optional files, inactive self-includes, and active cycles. Native watch ignores edits to inactive includes and switches branches after the configuration changes.
- [x] Repeated imports share a load by normalized source path. `TestAuthoredImportsLoadEachNormalizedSourceOnce` counts forwarded source requests for qualified, selected, and nested imports, including absent suffix candidates. Native watch rereads a previously selected include after an edit while it was inactive. Recipe cache reuse survives a change to an unused module and expires on a change to one the recipe reaches.
- [ ] Complete Phase 8 conformance. Includes that depend on declaration-local bindings are tracked in Phase 7.
- [x] Lexical `set` updates an existing uncaptured `let` in the same invocation. `TestKashAssignmentRequiresAnUncapturedLocalLet` covers invalid targets, nested invocation boundaries, and closure capture. `TestNativeKashSetUpdatesTheOwningBlock` covers loop, branch, and `with` assignment, multiple source fragments, and suspension without replay. `TestInteractiveAssignmentUsesSessionLetsAndRejectsCaptures` covers assignments across interactive entries and rejection before queuing work. A direct WASM probe also verifies assignment across `-c` fragments, suspension, and parse rejection before effects.
- [x] `TestSessionSharesLazyDefinitionsAndKeepsParserBoundaries` verifies that consumers share a lazy definition. `TestNativeKashLetShadowsFromItsDeclaration` verifies that the newer initializer sees the earlier value and prior closures keep the earlier lexical slot. It also covers shadowing across source fragments. Native and WASM probes cover those cases and assignment in a Kame value block. `TestInteractiveLetShadowsWithinOneEntry` verifies shadowing and capture within one session entry.
- [ ] Reclaim shadowed interactive slots from multi-statement entries when their last closure or retained statement releases them.
- [x] `set env/NAME` shares writes across functions and interactive or command-line fragments. Capture units fork the overlay, `with :env` affects stage environments, and deferred external commands read the overlay at cleanup. Recipe `authority` adds scoped `read` and `unset` access. Native and WASM checks cover writes, capture and cleanup, removal, and stage overrides.
- [x] Command lookup follows changes to the unit's `PATH`. Explicit tool overrides take precedence, stage-level `:PATH` affects only the child, and scoped run grants still require explicit executable paths. Native and WASM checks cover authored path search and overridden tools.
- [x] Direct `cd` changes the shared execution unit's working directory. Native and WASM checks cover function calls, capture isolation, previous and home directories, stage-level `:cwd`, shell payloads, deferred execution, and relative write grants. Interactive environment changes use `set env/NAME`.
- [x] Record effective child environment digests per stage, including unit edits and stage overrides. Reuse proof validation compares only inherited assignments the child consumes. Removed-name reads record absence independently of invocation values. Native and WASM probes verify file and cached-task reuse across changes to overridden values, and rerun after a consumed inherited value changes.
- [x] An unset `PATH` stops bare-name directory search and leaves explicit tool overrides usable. Native and WASM checks cover both cases.
- [ ] Verify platform-specific overridden `PATH` lookup beyond the current POSIX host.
