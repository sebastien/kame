# Plan 055 Phase 2 verification notes

- [x] Unify source dispatch for `.km` and `.kame`. Native and WASM discover `Kamefile`, `Makefile.km`, `make.km`, and `src/km/main.km` in order and parse them as Kame programs. See `TestNativeDiscoversKameProgramsInSpecificationOrder`. Explicit file dispatch recognizes `Kamefile` and the case-sensitive `.kame` alias. See `TestRunKamefileLanguage` and `TestRunInferredLanguagesAndInlineAuthority`. Build commands use Kame grammar for explicit `-f` and inline `-c` sources, and the CLI rejects the `kmk` language and stops inferring it from `.kmk`. See `TestBuildInspectionUsesKameGrammarForExplicitAndInlineSources`. JavaScript embedding defaults to Kame grammar for compile, evaluate, build, and watch. Python infers the unified Kame source suffixes, uses file grammar for compilation, and accepts Kame programs for evaluation, builds, and watches. Native and WASM explicit source runs validate rule-only options after reading their declarations, enabling the Python build job limit. Verified by the Python embedding suite and native/WASM CLI probes. The raw WASM source export and synchronous query use Kame file and expression grammar. Build descriptors default to Kame file grammar and runner descriptors reject the removed dialect. Combined native and WASM compilation always bounds syntax to one source fragment. The Go WASM constructors also use Kame file grammar, with the migrated fixtures retaining cache, service, and foreign-shell behavior checks. Production code no longer infers or accepts `.kmk` as a source language. Phase 12 covers the remaining explicit inspection modes, and Phase 13 covers the repository-wide filename conversion.
- [x] Finish definition headers and bodies. Kame and Kash share block-bodied `def` header parsing, including explicit `()` for zero parameters. See `TestKameFunctionBodySharesActionGrammar` and `TestKashFunctionsUseNativeIndentedBodies`. Both grammars reject parenthesized function headers and the formatter keeps long `def` headers on one line. See `TestFunctionHeadersRequireDefInBothSourceGrammars` and `TestLongDefHeaderKeepsParametersOnOneLine`. Block-valued definitions distinguish indented statements from continued expressions in Kame and Kash. The native test selects a record field from a typed block return. See `TestValueBlockDisambiguatesContinuedExpressions` and `TestNativeBlockValuedDefinitionReturnsTypedValue`. Pure declaration evaluation supports eager local bindings, conditionals, match, list and while loops, and typed returns from value blocks. Process commands remain an error at the authored statement. See `TestNativeConditionalRulesSelectOnlyActiveDeclarations` and the matching WASM include-selection probe. Assignment execution remains in Phase 4.
- [x] Parse and format block statements. Kash blocks now use exact local indentation prefixes, including independently indented branches. Statement `match` uses `PATTERN =>` arms with typed subjects, indented bodies, and inline expression results. Operandless `return` returns `nil` and operandless `exit` exits with status zero. See `TestKashBlocksUseExactLocalPrefixes`, `TestKashStatementMatchUsesArrowArms`, `TestNativeKashStatementMatchSelectsTypedAndPatternArms`, and `TestNativeKashTransfersWithDefaultOperands`. `set NAME = EXPR`, `set env/NAME = EXPR`, and `yield EXPR` have typed statement ASTs and canonical formatting. See `TestKashAssignAndYieldAreValueStatements` and `TestNestedGeneratorDoesNotChangeEnclosingReturn`. `if`, `elif`, and `while` use value-only headers. Native and WASM execute explicit process-graph conditions such as `$?(test -f ./ready).ok`, and accepted nonzero exits report `state: :completed` with `ok: false`. See `TestKashConditionsUseValueGrammar` and `TestNativeKashConditionsUseValuesAndExplicitProcessOutcomes`. Kash and Kash rule bodies reject bare bindings and use full value expressions for explicit initializers. Kame program-level bindings keep the shorthand. See `TestKashRequiresExplicitBindingsInAllBlockContexts`. Kash list and record iteration headers accept full value expressions. The terminal record frame remains a literal, and record source recovery remains invalid. See `TestKashLoopsParseFormatAndRejectInvalidHeaders`, `TestKashRecordLoopParsingAndFormatting`, and `TestNativeKashLoopsEvaluateValueHeaders`. The parser suite also covers `break`, `continue`, `defer`, `with`, `stream`, and parenthesized expression statements. Assignment execution and complete invocation outcome support are scheduled in Phases 4 and 5.
