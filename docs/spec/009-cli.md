# Command-Line Interface

## Purpose

The CLI exposes the native runtime without defining runtime semantics. Primary
invocation materializes targets; inspection and language tools live below the
`do` namespace.

## Invocation

```text
littlemake [OPTIONS] [TARGET...]
littlemake do COMMAND [OPTIONS] [ARG...]
```

Initial primary options are:

```text
-f, --file FILE       use one build file
-c, --command TEXT    use inline build source
-C, --directory DIR   set working directory
-j, --jobs N          maximum concurrent nodes, N > 0
-n, --dry-run         plan and render without effects or processes
--force               ignore freshness and cached-task hits
--json                 emit machine-readable events
```

Unknown options and missing values are CLI diagnostics. Options following `--`
are target names, not process arguments.

Simultaneous `--command` and `--file` is `LM-CLICF`. A non-integer or nonpositive
jobs value is `LM-CLIIV`.

## Source Discovery

After rejecting simultaneous `--command` and `--file`, source discovery order
is:

1. `--command`.
2. `--file`.
3. First existing path among `Makefile.lmk`, `make.lmk`, and
   `src/lmk/main.lmk` beneath the working directory.

Positional `.lm` and `.lmk` values remain target names; they are not implicit
source files.

Without source, the CLI prints a concise error and discovery paths. It does not
silently create a build file. This is `LM-CLINS`; an explicitly requested source
that cannot be read is `LM-FSERR`.

## Target Selection

Explicit targets run in argument order while sharing one engine. Without
targets, `default` is selected when present. Otherwise the CLI lists literal
named targets and exits successfully without running them.

A target named `do` is requested after `--` or with a future explicit target
option; bare `do` enters the tool namespace.

## Primary Output

Human output writes target status to stderr and recipe stdout/stderr to their
corresponding streams. Successful definition values requested as targets are
written to stdout. File artifact content is not printed during normal
materialization.

`--json` emits every status, process chunk, diagnostic, and terminal event as one
JSON object per line on stdout; stderr remains unused after argument parsing.
Binary process chunks are encoded as UTF-8 text when valid and otherwise as
base64 with an explicit encoding field. Runtime failures are error events.

Every JSON object contains `schema: 1`, `type`, and a type-specific payload.
Checked-in golden objects define AST, plan, diagnostic, stream, and terminal
shapes before the corresponding command is complete.

## Commands

### Plan

```text
littlemake do plan [OPTIONS] TARGET...
```

Print selected rule, captures, declared inputs, outputs, and freshness without
evaluating body effects or running processes.

### Run

```text
littlemake do run [OPTIONS] TARGET...
```

Materialize targets while exposing all execution events. It accepts shell,
timeout, retry, cwd, environment, dry-run, log-limit, and JSON options.

Primary invocation and `do run` share the same runtime path; `run` changes event
presentation and options rather than execution semantics.

### Parse

```text
littlemake do parse --lang expr|template|rule|script [FILE]
```

Parse input and print a stable JSON AST for tooling. Missing file reads stdin.
AST JSON includes source spans but not allocator or pointer details.

### Format

```text
littlemake do fmt [--lang LANG] [-i | -n] FILE...
```

Default output is formatted source. `-i` replaces each file atomically. `-n`
prints files that would change and exits 1 when any differ. Formatting stdin is
supported only without `-i` or `-n`.

### Cat

```text
littlemake do cat TARGET
```

Materialize a target, then write exact file bytes or definition value without
adding a newline. Tasks without an artifact fail with `LM-NOART`.

### Graph Inspection

```text
littlemake do inputs [--depth N] TARGET
littlemake do outputs [--depth N] TARGET
littlemake do span [--expand] [--depth N] TARGET
```

Depth zero returns no edges; one returns direct edges; `-1` is unlimited.
Outputs are stable JSON arrays. `span` separates statically known and
evaluation-dependent resources; `--expand` evaluates dynamic definitions but
does not execute recipes.

### Expression

```text
littlemake do expr [-c TEXT | FILE] [CAPABILITY OPTIONS] [-- ARG...]
```

Expression tools expose `args` and `cwd`. Environment is available only through
the authorized `env` operation. Capabilities are denied by default and granted
with:

```text
--allow-read[=ROOTS]
--allow-write[=ROOTS]
--allow-run
--allow-env[=NAMES]
```

Normal build execution grants read and write within cwd and grants process
execution. It copies the complete CLI environment into recipe process requests,
where cached tasks fingerprint it. Language-level environment reads and access
outside cwd remain denied unless an explicit option grants them.

## Diagnostics

Human diagnostics use:

```text
source:line:column: severity CODE: message
source line
        ^ span
note: additional context
```

Stable codes and severities are defined only by `011-diagnostics.md`.

Suggestions are deterministic and limited to known operations, definitions, or
targets. Path-like unknown targets should suggest an explicit `./` where useful.

## Signals and Exit Status

The first `SIGINT` or `SIGTERM` cancels active roots and begins process-group
shutdown. A repeated signal may terminate immediately using the conventional
signal exit status.

Exit status is:

- 0 for successful execution, successful inspection, or target listing.
- 1 for parse, evaluation, build, cache, or `fmt -n` differences.
- 2 for CLI usage errors.
- 128 plus signal number for forced signal termination.

With multiple targets, any failed target makes the final status nonzero.

## Acceptance Tests

- Source discovery follows the documented order.
- Positional `.lmk` text is treated as a target.
- No target selects `default` or lists targets when it is absent.
- Multiple roots share one dependency execution.
- `-j 0` is rejected; `-j 1` is deterministic.
- Dry-run performs no process, write, or output effect.
- Human process output remains on its original stream.
- JSON output is valid JSON Lines and safely represents binary chunks.
- `fmt -n` and `fmt -i` have the documented atomic behavior and statuses.
- `cat` adds no newline.
- Expression capabilities are denied by default.
- A first termination signal cleans up process groups before exit.
- CLI usage, build failure, and signal exits use the documented statuses.
