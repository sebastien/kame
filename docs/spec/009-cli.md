# Command-Line Interface

## Purpose

The CLI exposes the native runtime without defining runtime semantics. Primary
invocation materializes targets; inspection and language tools live below the
`do` namespace.

## Invocation

```text
kame [OPTIONS] [TARGET...]
kame do COMMAND [OPTIONS] [ARG...]
```

Initial primary options are:

```text
-f, --file FILE        use one build file
-c, --command TEXT     use inline build source
-C, --directory DIR    set working directory
-j, --jobs N           maximum concurrent nodes, N > 0
-n, --dry-run          plan and render without effects or processes
--force                ignore freshness and cached-task hits
--json                 emit machine-readable events
-h, --help             show an overview of the tool
-V, --version          show the version
```

Unknown options and missing values are CLI diagnostics. Options following `--`
are target names, not process arguments.

Simultaneous `--command` and `--file` is `OPT_CONFLICT`. A non-integer or nonpositive
jobs value is `OPT_VALUE_INVALID`.

## Help and Version

`-h` and `--help` print an overview of the tool to stdout and exit 0. Help takes
precedence over version and over normal execution. `kame do --help` (and a
bare `kame do`) lists the utility commands, and
`kame do COMMAND --help` prints command-specific usage.
`kame do help [COMMAND]` is equivalent.

`-V` and `--version` print `kame VERSION (BUILD_ID; BUILD_TIME; BUILD_MODE)` to stdout and exit 0.

A `-h`, `--help`, `-V`, or `--version` token after `--` is a target name, and one
used as the value of an option is that option's value; neither requests help or
version.

A bare invocation (no arguments) that finds no build source prints the overview
to stdout and exits 0 instead of reporting `BUILD_NO_SOURCE`. Any explicit
argument, including `-C`, restores the `BUILD_NO_SOURCE` diagnostic.

## Source Discovery

After rejecting simultaneous `--command` and `--file`, source discovery order
is:

1. `--command`.
2. `--file`.
3. First existing path among `Makefile.kmk`, `make.kmk`, and
   `src/kmk/main.kmk` beneath the working directory.

Positional `.km` and `.kmk` values remain target names; they are not implicit
source files.

Without source, the CLI prints a concise error and discovery paths, except for a
bare no-argument invocation, which prints the overview and exits 0 (see Help and
Version). It does not silently create a build file. This is `BUILD_NO_SOURCE`; an
explicitly requested source that cannot be read is `FS_ERR`.

File-backed sources may use top-level `include PATH` directives. Their paths are
relative to the containing source, are read before compilation, and merge their
definitions and rules into the same program in depth-first declaration order.

## Target Selection

Explicit targets run in argument order while sharing one engine. Without
targets, `default` is selected when present. When no `default` is defined, the
invocation fails with `TGT_NO_DEFAULT` and reports the available literal named
targets as a note. This selection is shared by every target-taking command: the
primary invocation and `plan`, `cat`, `inputs`, `outputs`, and `span`. A
target-less invocation never prints the target list to stdout.

A target named `do` is requested after `--` or with a future explicit target
option; bare `do` enters the tool namespace.

## Primary Output

Human output writes progress to stderr and recipe stdout/stderr to their
corresponding streams. Each lifecycle line identifies the target and reports
the active and completed counts; a final summary reports completed and failed
targets plus elapsed wall-clock time. Successful definition values requested as
targets are written to stdout. File artifact content is not printed during
normal materialization.

`--json` emits every status, process chunk, diagnostic, and terminal event as one
JSON object per line on stdout; stderr remains unused after argument parsing.
Binary process chunks are encoded as UTF-8 text when valid and otherwise as
base64 with an explicit encoding field. Runtime failures are error events.

Every JSON object contains `schema: 1`, `type`, and a type-specific payload.
Execution events additionally expose their resource key, source span when
known, discovered dependency, effect kind, and typed target value when
applicable. These are additive schema-1 fields. Checked-in golden objects
define AST, plan, diagnostic, stream, and terminal shapes before the
corresponding command is complete.

## Commands

### Help

```text
kame do help [COMMAND]
```

Print the tool overview, the command list, or one command's usage and options.
With no COMMAND it is equivalent to `kame do --help`.

### Plan

```text
kame do plan [OPTIONS] [TARGET...]
```

Print selected rule, captures, declared inputs, outputs, and freshness without
evaluating body effects or running processes. With no TARGET, `default` is
selected as in Target Selection.

### Parse

```text
kame do parse --lang expr|template|rule|script [FILE]
```

Parse input and print a stable JSON AST for tooling. Missing file reads stdin.
AST JSON includes source spans but not allocator or pointer details.

### Format

```text
kame do fmt [--lang LANG] [--indent tabs|spaces] [--indent-width N] [-i | -n] FILE...
```

Default output is formatted source. `-i` replaces each file atomically. `-n`
prints files that would change and exits 1 when any differ. Formatting stdin is
supported only without `-i` or `-n`.
Rule bodies use tabs by default. `--indent spaces` selects spaces, with four
spaces by default; `--indent-width N` selects a width from 1 to 16. The width
option applies when spaces are selected. These options affect `rule` and
`script` formatting only.
Formatting canonicalizes whitespace within syntax and recipe indentation while
preserving the number of blank lines between script items, between recipe lines,
and at the beginning and end of script input. A blank line between a rule header
and its first recipe line is not part of the recipe and is removed. Whitespace
on otherwise blank lines is removed.

### Cat

```text
kame do cat [TARGET]
```

Materialize a target, then write exact file bytes or definition value without
adding a newline. Tasks without an artifact fail with `NO_ARTIFACT`. With no
TARGET, `default` is selected as in Target Selection.

### Graph Inspection

```text
kame do inputs [--depth N] [TARGET]
kame do outputs [--depth N] [TARGET]
kame do span [--expand] [--depth N] [TARGET]
```

With no TARGET, `default` is selected as in Target Selection.

Depth zero returns no edges; one returns direct edges; `-1` is unlimited.
Outputs are stable JSON arrays. `span` separates statically known and
evaluation-dependent resources; `--expand` evaluates dynamic definitions but
does not execute recipes.

### Expression

```text
kame do expr [-c TEXT | FILE] [CAPABILITY OPTIONS] [-- ARG...]
```

Expression tools expose `args` and `cwd`. Environment is available only through
the authorized `env` operation. Capabilities are denied by default and granted
with:

```text
--allow-read[=ROOTS]
--allow-write[=ROOTS]
--allow-run
--allow-env[=NAMES]
```

Normal build execution grants read and write within cwd and grants process
execution. It copies the complete CLI environment into recipe process requests,
where cached tasks fingerprint it. Language-level environment reads and access
outside cwd remain denied unless an explicit option grants them.

## Diagnostics

Human diagnostics use the structured model and information hierarchy in
`011-diagnostics.md`: outcome, authored source location, established reason,
propagation or target context, concrete recovery help, then any underlying
process cause. The source excerpt and marker use one-based locations and
tab-aware display columns. A missing source span does not invent a synthetic
location.

`--color auto|always|never` and `--diagnostic-format human|plain` are global
presentation controls specified by `011-diagnostics.md`. They do not alter
execution or JSON output. `auto` follows terminal and documented colour
environment controls; plain output remains deterministic and unstyled.

Stable codes, severities, structured context, and JSON parity are defined only
by `011-diagnostics.md`.

Suggestions are deterministic and limited to known operations, definitions, or
targets. Path-like unknown targets should suggest an explicit `./` where useful.

## Signals and Exit Status

The first `SIGINT` or `SIGTERM` cancels active roots and begins process-group
shutdown. A repeated signal may terminate immediately using the conventional
signal exit status.

Exit status is:

- 0 for successful execution, successful inspection, target listing, or a
  help or version request.
- 1 for parse, evaluation, build, cache, or `fmt -n` differences.
- 2 for CLI usage errors.
- 128 plus signal number for forced signal termination.

With multiple targets, any failed target makes the final status nonzero.

## Acceptance Tests

- Source discovery follows the documented order.
- Positional `.kmk` text is treated as a target.
- No target selects `default`; when it is absent the invocation fails with
  `TGT_NO_DEFAULT` and reports the available targets.
- Multiple roots share one dependency execution.
- `-j 0` is rejected; `-j 1` is deterministic.
- Dry-run performs no process, write, or output effect.
- Human process output remains on its original stream.
- JSON output is valid JSON Lines and safely represents binary chunks.
- `fmt -n` and `fmt -i` have the documented atomic behavior and statuses.
- `cat` adds no newline.
- Expression capabilities are denied by default.
- `--help` and `--version` write to stdout and exit 0; help wins over version.
- A help or version token after `--`, or used as an option value, is not a
  request.
- A bare invocation without a build source prints the overview and exits 0.
- `do` with no command lists the utility commands and exits 0.
- A first termination signal cleans up process groups before exit.
- CLI usage, build failure, and signal exits use the documented statuses.

The end-to-end conformance suite that exercises these acceptance tests through
the compiled binary is specified in `013-tests.md`.
